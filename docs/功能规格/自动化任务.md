# WeMonitor — 自动化任务

> 状态：已实现（2026-10-13）
> 展示 WeAuto 自动化任务的执行状态与历史，并支持手动触发。

---

## 1. 功能概述

`/auto` 页面为 [WeAuto](../../../WeAuto) 这个无端口 CLI 框架提供可视化：

- **状态卡**：每个任务显示今日结果、剩余流量、套餐到期、今日随机目标时刻、上次成功时间
- **执行历史**：最近 50 条业务级记录（时间 / 任务 / 状态 / 说明 / 耗时）
- **手动触发**：点击「立即执行」调 CLI 以 `--force` 跑一次

WeMonitor **不重复实现** WeAuto 的调度算法 —— 今日目标时刻由 CLI 的 `list --json` 提供。

---

## 2. 页面结构（`/auto`）

单页两张卡片，模板 `views/auto.ejs`：

| 区域 | 元素 id | 内容 |
|---|---|---|
| 卡片一 | `#auto-version` | 版本号与运行目录 |
| 卡片一 | `#auto-tasks` | 每个任务一张状态卡（由 JS 渲染） |
| 卡片二 | `#auto-stats` | 累计执行 / 成功 / 失败次数 |
| 卡片二 | `#auto-runs` | 执行历史表格 |

页内无专属 CSS，全部复用 `public/css/style.css` 的 `.card` / `.data-table` / `.status-badge` / `.btn` 等既有类。

侧边栏入口位于「服务管理」分组（`views/layout.ejs`），图标 `zap`，`active` 值为 `auto`。

## 3. API 端点

挂在 `routes/api.js` 的 `/api/v1` 前缀下，鉴权沿用该文件的 `requireAuth` + `status === 'active'` 内联校验。

| 方法 | 端点 | 说明 |
|---|---|---|
| `GET` | `/api/v1/auto/status` | 任务清单（含今日状态与上次成功）+ 全局最新记录 + 统计 |
| `GET` | `/api/v1/auto/runs?limit=N` | 执行历史（默认 50，上限 200，最新在前） |
| `POST` | `/api/v1/auto/trigger` | 手动触发，body `{ task }`；**同步等待**至执行结束 |

`/auto/status` 响应字段：

```jsonc
{
  "available": true,        // 任务清单是否获取成功（CLI 不可用时为 false）
  "error": null,
  "dir": "/home/sherlockguo/weauto",
  "version": "271209a",     // 读自 ~/weauto/.version
  "today": "2026-10-13",    // 按 Asia/Shanghai 计算
  "tasks": [{ "name", "displayName", "requires", "file", "window", "target",
              "todayStatus", "todayTime", "lastSuccess" }],
  "latest": {},             // 最近一条非 skipped 记录
  "lastSuccess": {},
  "stats": { "total", "success", "failed" }
}
```

## 4. 数据来源与跨仓库耦合点

`lib/api/auto.js` 通过三条途径访问 WeAuto：

| 途径 | 用途 |
|---|---|
| 读 `~/weauto/data/runs.jsonl` | 业务级执行记录（逐行解析，单行损坏即跳过） |
| 执行 `node ~/weauto/bin/weauto.mjs list --json` | 任务清单与今日目标时刻 |
| 执行 `node ~/weauto/bin/weauto.mjs run <task> --force` | 手动触发 |

**注意事项**：

- node 路径用 `process.execPath`，**不能用 `node`** —— cron/服务进程的 PATH 可能不含 node 所在目录。
- 命令用 `execFile`（数组传参）+ 90s 超时，**不经 shell**。
- 触发前先校验任务名（`/^[a-z0-9][a-z0-9-]{0,63}$/`）并确认任务已注册，杜绝任意字符串进入子进程。
- `WEAUTO_DIR` 可在 `lib/deploy/local.js` 中用环境变量覆盖，便于本地开发时指向源码目录。

**跨仓库契约**（编译期无法校验，改动任一侧需同步）：

1. `runs.jsonl` 的字段：`ts` / `time` / `date` / `task` / `status` / `message` / `data` / `dur` / `force`
2. `list --json` 的输出结构：`{ tasks: [{ name, displayName, requires, file, window, target }] }`
3. 状态取值：`success` / `already-signed` / `skipped` / `failed` / `blocked` / `network-error` / `config-error`

## 5. 关键文件

| 文件 | 用途 |
|---|---|
| `lib/api/auto.js` | 后端逻辑：读记录、调 CLI、触发 |
| `lib/deploy/local.js` | `WEAUTO_DIR` 常量；`getLocalState()` 对无端口服务返回 `alive: true` |
| `routes/api.js` | 挂载 3 个 `/auto/*` 端点 |
| `routes/pages.js` | `/auto` 页面路由 |
| `routes/deploy.js` | `SERVICES` 数组中的 WeAuto 条目（`port: null`） |
| `views/auto.ejs` | 页面模板 |
| `views/layout.ejs` | 侧边栏入口 + `svcGroupActive` 数组 |
| `public/js/auto.js` | 前端渲染与交互 |

**无端口服务的处理**：WeAuto 没有监听端口，若直接传 `null` 给 `probePort` 会抛错并使 `/api/v1/deploy/status` 整体 500。因此 `getLocalState()` 在 `port` 为空时直接返回 `alive: true`，使 `computeSummary` 走到版本比较分支，而不是误判 `stopped`。

## 6. 已知限制

1. **手动触发是同步等待** —— 前端按钮在请求期间置灰，最长等 90s（受 `execFile` 超时限制）；无「执行中」的状态轮询。
2. **无自动刷新** —— 页面加载时拉取一次，需手动点刷新或重新进入。
3. **`available: false` 只提示不重试** —— CLI 路径不可用时页面显示警告横幅，需人工排查。
4. **历史记录不轮转** —— 与 WeAuto 的 `runs.jsonl` 共用同一份数据，未在 WeMonitor 侧做截断管理。
5. **状态文案为中文硬编码** —— 见 `public/js/auto.js` 的 `AUTO_STATUS` 映射表，新增状态需同步维护（未映射的状态会原样显示）。
